# Security Policy

Security is an important part of maintaining the projects we build.

If you discover a security vulnerability in a Lylink project, please report
it privately rather than opening a public issue.

## Reporting a vulnerability

Whenever available, use the repository's private security reporting
mechanism.

If a project does not provide one, contact the Lylink Wardens privately.

Please include as much relevant information as possible, such as:

- A description of the vulnerability
- Steps to reproduce it
- The potential impact
- A proof of concept, if available
- Any suggested mitigation

## Responsible disclosure

Please avoid publicly disclosing a vulnerability until the project has had
a reasonable opportunity to investigate and address it.

Security reports are handled in good faith. Contributors who responsibly
report vulnerabilities will be treated with respect and their contributions
will be acknowledged where appropriate.

## Project-specific policies

Individual Lylink projects may define additional security policies or
reporting procedures. When they do, those policies take precedence for that
project.
